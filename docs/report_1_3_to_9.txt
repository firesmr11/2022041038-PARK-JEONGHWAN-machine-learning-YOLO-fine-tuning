1.3 전체 수행 과정

본 과제는 직접 촬영한 컵, 마우스, 리모컨의 이미지를 이용하여 데이터 구축, 라벨링, 모델 학습, 테스트 평가, 영상 감지 및 추적 순서로 진행하였다. Roboflow의 자동 라벨링 결과를 수동으로 검토한 뒤 학습·검증·테스트 데이터로 분할하였다.

모델은 사전 학습된 YOLOv8n을 사용하였다. 학습 이미지 196장과 414장에 대해 각각 25회, 50회, 75회 학습하였으며, Google Colab T4와 로컬 RTX 4060 환경에서 총 12개 조건을 비교하였다. 각 실험의 best.pt를 동일한 테스트셋으로 평가하고, 두 환경의 대표 모델을 새로운 영상에 적용하였다.

최종 영상은 약 13.43초의 원본 전체에 감지·추적을 수행한 후 2배속을 적용하여 약 6.72초로 제작하였다. 결과 수치, 주요 실패 사례, 실행 코드와 모델을 제출용 로컬 Git 저장소에 정리하였다.

2. 데이터세트 구축

2.1 직접 촬영 방법

컵, 마우스, 리모컨을 직접 촬영하였으며 위쪽, 측면, 비스듬한 방향 등 촬영 각도를 바꾸었다. 촬영 거리를 조절하여 물체가 크게 보이는 경우와 작게 보이는 경우를 포함하였고, 책상과 침구 등 배경의 색상과 질감을 달리하였다.

컵은 손잡이 방향과 입구가 보이는 정도를 바꾸었고, 마우스는 앞면과 측면을 포함하였다. 리모컨은 버튼이 있는 앞면과 뒷면, 회전된 모습을 촬영하였다. 조명과 그림자 차이도 포함하여 특정 구도에만 의존하지 않도록 구성하였다.

2.2 단독 물체·복수 물체·손 가림 사진 구성

단독 물체 사진은 각 클래스의 기본적인 외형을 학습하도록 구성하였다. 복수 물체 사진은 컵과 리모컨 등 서로 다른 클래스가 한 화면에 등장하는 상황을 포함하였다. 한 이미지에 여러 감지 대상이 있으면 각각 별도의 바운딩 박스를 부여하였다.

물체를 손으로 잡거나 사용하는 사진도 포함하였다. 손은 별도 클래스로 학습하지 않고 컵·마우스·리모컨만 라벨링하였다. 이를 통해 물체가 일부 가려지는 실제 사용 상황을 반영하고자 하였다.

2.3 Roboflow 자동 라벨링 및 수동 검토

클래스 이름을 cup, mouse, remote로 통일하고 Roboflow의 자동 라벨링을 수행하였다. 이후 객체 누락, 클래스 오분류, 박스 범위 오류, 중복 박스를 수동으로 확인하였다. 검토를 마친 이미지를 승인하여 데이터세트에 추가하고 YOLOv8 형식으로 내려받았다.

다운로드 후에는 코드로 클래스 목록, 이미지 수, 라벨 파일과 객체 수를 검사하였다. 최종 확인한 학습·검증·테스트 분할에는 라벨 박스가 없는 이미지가 0장이었다.

2.5 학습·검증·테스트 데이터 분할

학습셋은 가중치를 갱신하는 데 사용하고, 검증셋은 학습 중 성능 확인과 최적 체크포인트 선택에 사용하였다. 테스트셋은 학습이 끝난 모델의 성능을 평가하는 데 사용하였다.

데이터 증가 효과를 비교하기 위해 검증 39장과 테스트 19장은 유지하고 학습 데이터에만 이미지를 추가하였다. 기존 로컬 실험 기록에서는 두 버전의 검증·테스트 이미지와 라벨의 해시가 일치함을 확인하였다. 다만 파일 해시 검사로 유사 구도나 같은 촬영 장면의 분할 간 관계까지 판단할 수는 없다.

2.6 학습 데이터 추가 수집 및 버전 관리

추가 사진 218장을 학습셋에 포함하여 학습 이미지 수를 196장에서 414장으로 늘렸다. 이는 약 2.11배 증가한 규모이다. 추가 이미지도 촬영 조건을 바꾸어 수집하고 라벨링과 검토를 수행하였다.

Roboflow에서 초기 데이터는 버전 1, 확장 데이터는 버전 2로 관리하였다. 결과 폴더와 모델 이름에는 환경, 학습 이미지 수, 에포크 수를 표시하였다. 예를 들어 local_196_75_best.pt는 로컬 환경에서 학습 이미지 196장으로 75회 학습하는 동안 선택한 모델이다.

3. 모델 및 실행 환경

3.1 YOLOv8n과 사전 학습 모델 활용

제한된 자원으로 여러 실험을 수행하기 위해 비교적 작은 YOLOv8n을 사용하였다. 사전 학습 가중치 yolov8n.pt에서 시작하여 세 클래스에 맞게 학습하였다.

각 조건은 원래 사전 학습 가중치에서 독립적으로 시작하였다. 25회 학습한 모델을 이어서 50회 모델로 만드는 방식은 사용하지 않았다. 따라서 실험은 각 학습 한도에서 선택한 최적 모델을 비교하는 구조이다.

3.2 Google Colab T4 환경

Colab에서는 NVIDIA Tesla T4 GPU를 사용하였다. 최종 학습 로그의 환경은 Python 3.13.16, PyTorch 2.14.1+cu130, Ultralytics 8.4.216이었다.

Colab은 로컬 GPU 환경 설정의 부담을 줄일 수 있었지만, 런타임이 종료되거나 새로 할당되면 패키지와 변수를 다시 준비해야 했다. 결과 손실을 방지하기 위해 Google Drive를 연결하여 학습 결과를 저장하였다.

3.3 로컬 RTX 4060 환경

로컬 실험은 NVIDIA GeForce RTX 4060이 탑재된 Windows 노트북에서 수행하였다. 같은 데이터 버전과 주요 학습 조건을 적용하여 결과를 비교하였다.

로컬은 결과 파일을 직접 보관할 수 있고 클라우드 세션 종료의 영향을 받지 않는 장점이 있었다. 반면 Python과 GPU용 PyTorch 환경을 직접 준비해야 했다. 학습 시간에는 GPU 외에도 CPU, 저장장치, 전원 설정 등이 영향을 줄 수 있음을 고려하였다.

3.4 공통 학습 설정과 결과 저장 방법

주요 설정은 초기 모델 yolov8n.pt, 입력 크기 640, 배치 크기 16, seed 0, workers 2, optimizer auto였다. 비교 학습은 patience 0을 사용하도록 구성하였다. 초기 Colab 196장·50회 실험은 patience 15였으나 실제로 50회를 모두 완료하였다.

각 실험에서 best.pt, last.pt, results.csv, results.png, args.yaml 등을 보관하도록 하였다. Colab은 Drive에 저장하고 ZIP으로 백업하였으며, 로컬 결과는 실험별 폴더로 관리하였다. 현재 제출 자료에는 실제 확보한 모델 7개, 비교표와 체크포인트에서 복원한 학습 이력을 포함하였다.

학습 입력 크기가 같더라도 데이터 버전 생성 단계의 전처리가 다르면 비교에 영향을 줄 수 있다. 따라서 전처리와 모든 세부 설정이 완벽히 동일한 통제 실험으로 단정하지 않았다.

4. 실험 설계 및 평가 방법

4.1 학습 에포크 비교

25회, 50회, 75회 학습을 비교하였다. 에포크 증가에 따른 성능 향상 여부와 추가 학습에 필요한 시간을 함께 확인하였다. 모든 비교는 각 학습 한도 안에서 검증 성능으로 선택한 best.pt를 기준으로 하였다.

4.2 학습 데이터 증가 비교

학습 이미지 196장과 414장을 비교하였다. 검증 39장과 테스트 19장은 유지하였다. 각 데이터 규모에서 25회, 50회, 75회를 실행하여 데이터 증가 효과가 학습 횟수에 따라 달라지는지도 확인하였다.

4.3 실행 환경 비교

Colab T4와 로컬 RTX 4060에서 동일한 데이터 수와 에포크 조합을 실행하였다. 전체 실험 수는 2개 환경 × 2개 데이터 규모 × 3개 에포크로 총 12개이다. 결과는 실행 환경 단위의 비교이며 GPU만의 인과적 효과로 해석하지 않았다.

4.4 평가 지표

Precision은 객체라고 예측한 결과 중 올바른 감지의 비율이고, Recall은 실제 객체 중 올바르게 감지한 비율이다. mAP50은 IoU 0.50 기준의 클래스별 AP를 평균한 값이다. mAP50-95는 IoU 0.50부터 0.95까지 여러 기준의 AP를 평균하여 더 엄격한 박스 위치 일치 조건을 포함한다.

본 실험은 모든 모델의 mAP50이 99.50%였으므로 모델 간 차이를 분석할 때 mAP50-95를 중심으로 비교하였다. mAP는 단순한 정답 이미지 비율과 같은 의미의 정확도가 아니다.

4.5 검증 성능에 따른 best.pt 선택

best.pt는 검증 성능을 기준으로 선택한 가중치이며 마지막 에포크 가중치와 다를 수 있다. 실제로 최종 로컬 후보는 75회 학습 중 66번째 에포크에서, Colab 후보는 50회 학습 중 49번째 에포크에서 가장 높은 기록상 검증 mAP50-95를 보였다.

따라서 '75회 모델'은 75번째 가중치 자체가 아니라 75회 학습 한도에서 선택한 모델을 의미한다. 각 모델 내부 체크포인트 선택은 검증셋으로 수행하였지만, 실험 간 최종 후보 선택에는 테스트 결과도 참고하였으므로 추가 독립 평가가 필요하다.

4.6 동일한 테스트셋을 이용한 평가 방법

모든 모델에 테스트 이미지 19장과 객체 26개를 동일하게 적용하였다. 테스트 객체는 컵 10개, 마우스 6개, 리모컨 10개이다. 모델과 데이터 설정을 불러온 뒤 split=test를 지정하여 학습 없이 평가하였다.

전체 지표와 클래스별 결과를 확인하고 비교표로 저장하였다. 테스트 크기가 작으므로 소수점 수준의 차이를 확정적인 우열로 해석하지 않았다.

414장·50회 모델은 마우스와 리모컨에서 높은 박스 일치 성능을 보였으며 컵은 상대적으로 낮았다. 컵의 손잡이 방향과 원근 변화가 박스 범위에 영향을 주었을 가능성이 있으나 개별 사례 분석 없이 원인으로 확정하지 않았다. 테스트 객체 수가 클래스별 6~10개에 불과하다는 점도 고려하였다.

5.4 학습 데이터 증가 전후 성능 비교

| 환경 | 에포크 | 196장 mAP50-95 | 414장 mAP50-95 | 변화 |
|---|---:|---:|---:|---:|
| Colab | 25 | 96.94% | 98.17% | +1.23%p |
| Colab | 50 | 96.26% | 98.50% | +2.24%p |
| Colab | 75 | 98.34% | 98.31% | -0.03%p |
| 로컬 | 25 | 95.81% | 97.63% | +1.83%p |

| 로컬 | 75 | 98.73% | 96.94% | -1.79%p |

로컬 변화량은 반올림 전 값으로 계산하였다. 데이터 증가 효과는 모든 조건에서 일관되지 않았다. 추가 데이터의 수뿐 아니라 다양성, 클래스 구성, 라벨 품질, 학습 설정과 평가 표본이 결과에 영향을 줄 수 있다. 따라서 데이터 수만 늘리면 항상 성능이 좋아진다는 결론은 내리지 않았다.

5.5 Colab·로컬 학습 시간 및 성능 비교

로컬 results.csv의 마지막 누적 시간은 다음과 같다.

| 학습 이미지 | 에포크 | 학습 시간 |
|---|---:|---:|
| 196장 | 25 | 82.6초 |
| 196장 | 50 | 155.1초 |

데이터와 에포크가 증가할수록 로컬 학습 시간이 증가하였다. Colab의 196장·50회 완료 로그는 0.151시간으로 약 543.6초였으며, 같은 조건의 로컬 CSV 기록은 약 155.1초였다. 이 기록에서는 로컬이 짧았지만 측정 범위와 주변 실행 조건이 완전히 같다고 확인된 자료는 아니므로 정확한 GPU 속도 배수로 제시하지 않았다.

테스트 성능의 환경별 우열도 조건에 따라 달랐다. 예를 들어 414장·50회는 Colab이 높았으나 196장·75회는 로컬이 높았다. 환경과 성능의 관계를 단일 원인으로 설명하기 어렵다는 점을 확인하였다.

5.6 오검출·미검출 사례 분석

새 영상의 원본 약 3.50초에서 로컬 모델이 실제 마우스를 cup으로 잘못 분류하였다. 이때 실제 컵도 별도로 감지되었으므로 컵 자체에 중복 박스가 생긴 사례와 구분하였다. Colab은 해당 시점의 마우스를 올바르게 감지하였다.

반면 Colab은 약 7.00초에 컵 박스가 겹치거나 손과 마우스 영역까지 크게 확장되는 장면을 보였다. 약 7.80초에는 가까이 들어 올린 마우스가 컵을 크게 가렸고 두 모델 모두 컵을 출력하지 않았다. 가려진 객체에 대한 정답 기준이 없으므로 이 상황을 그대로 정량적인 미검출률로 계산하지 않았다.

이러한 사례는 정적 테스트 지표가 높더라도 움직임, 가림, 거리 변화가 있는 영상에서 오분류와 박스 불안정이 발생할 수 있음을 보여 준다.

5.7 소규모 테스트셋과 실험 결과의 한계

테스트셋이 19장·26객체로 작고 같은 실물 물체와 유사한 배경을 중심으로 구성되어 있다. 따라서 다른 형태의 컵이나 다른 제품의 마우스·리모컨에서도 같은 성능이 나타나는지는 확인하지 못하였다.

각 조건은 단일 seed의 결과이며 반복 실험의 평균과 분산을 구하지 않았다. 학습 중 best.pt 선택은 검증 기준이지만 실험 간 최종 후보 선택에는 테스트 결과를 참고하였다. 그러므로 새로운 촬영 세션의 독립 데이터에서 추가 검증할 필요가 있다.

6. 객체 감지·추적 영상 제작

6.1 원본 영상 촬영 조건

새 원본 영상은 책상 위의 컵, 마우스, 리모컨을 차례로 잡아 움직이는 장면으로 촬영하였다. 해상도는 1080×1920, 프레임률은 30fps이며 403프레임, 약 13.43초로 구성되어 있다.

컵의 이동, 마우스를 카메라 가까이 들어 올리는 동작, 리모컨 조작을 포함하였다. 세 클래스의 정지 상태와 손 가림, 거리 변화에 따른 동작을 한 영상에서 확인하였다.

6.2 학습 모델과 추적 알고리즘 적용

로컬의 196장·75회 모델과 Colab의 414장·50회 모델에 동일한 원본 프레임을 적용하였다. 두 모델 모두 입력 크기 640, 신뢰도 임곗값 0.25, NMS IoU 0.70, FP32, CPU 추론 조건을 사용하였다.

추적에는 ByteTrack을 사용하고 프레임 사이 상태를 유지하도록 설정하였다. 객체 박스와 클래스, 신뢰도, 추적 ID를 표시하고 박스 중심점의 이동 궤적을 시각화하였다. 이번 영상 비교는 두 학습 모델의 동작 비교이며 GPU 추론 속도 비교가 아니다.

6.3 전체 2배속 결과 영상 및 주요 장면

원본 403프레임 전체에 추적을 수행한 뒤 재생 속도만 2배로 변경하였다. 앞뒤 구간은 자르지 않았다. 결과는 60fps, 약 6.72초의 무음 영상이며 세 물체를 조작하는 전체 과정을 유지한다. 강의자료에는 5초 분량으로 안내되어 있으나 현재 제작본은 전체 구간 유지 방침에 따른 약 6.72초이며 정확한 5초 영상은 아니다.

| 원본 시각 | 관찰 결과 |
|---|---|
| 0.00초 | 두 모델 모두 세 클래스를 감지하였다. |
| 3.50초 | 로컬은 마우스를 cup으로 오분류하고 Colab은 mouse로 감지하였다. |
| 6.30초 | 로컬의 컵 ID는 1, Colab의 컵 ID는 6으로 확인되었다. |
| 7.00초 | Colab의 컵 박스 중복과 범위 확장이 관찰되었다. |
| 7.80초 | 마우스를 가까이 들어 올려 컵이 크게 가려졌고 두 모델의 컵 출력이 없었다. |
| 8.50초 | Colab의 실제 컵 ID는 3, 마우스 ID는 13으로 바뀌었다. |
| 11.50~13.30초 표본 | 로컬의 리모컨·마우스 주요 ID는 유지되었고 Colab은 리모컨 13, 마우스 25로 변경되었다. |

표의 시간은 원본 기준이다. 2배속 재생에서는 해당 시각의 절반에 장면이 나타난다. 로컬·Colab 개별 영상과 좌우 비교 영상을 함께 제작하였다.

6.4 움직임·손 가림 상황에서의 감지와 추적 ID 유지

시작과 종료 장면에서 로컬 모델의 주요 ID는 컵 1, 마우스 3, 리모컨 2로 같았다. Colab 모델은 초기 컵 1, 마우스 3, 리모컨 2에서 종료 표본의 컵 3, 마우스 25, 리모컨 13으로 바뀌었다. 주요 장면에서는 로컬 모델의 연결이 상대적으로 안정적이었다.

그러나 시작과 종료 ID가 같다고 영상 전체에서 완벽하게 추적했다는 의미는 아니다. 로컬에도 일시적인 오분류와 추가 박스가 있었다. 프레임별 정답 박스와 정답 ID를 구축하지 않았으므로 정식 ID 전환 횟수, IDF1과 영상 mAP는 계산하지 않았다.

7. 문제 해결 과정 및 경험

7.1 데이터 증가 효과를 공정하게 비교하기 위한 데이터 관리

학습 데이터를 추가하는 과정에서 가장 중요했던 문제는 기존 실험과 확장 실험의 평가 조건을 유지하는 것이었다. 데이터를 추가한 뒤 전체 이미지를 다시 무작위 분할하면 검증셋과 테스트셋까지 바뀔 수 있다. 이 경우 성능이 달라져도 학습 데이터 증가 때문인지, 평가 이미지의 난이도가 달라졌기 때문인지 구분하기 어렵다.

이를 방지하기 위해 기존 검증 이미지 39장과 테스트 이미지 19장은 유지하고, 추가 촬영한 이미지는 학습셋에만 포함하였다. 이에 따라 학습 이미지는 196장에서 414장으로 증가하였지만 평가에 사용하는 데이터는 동일하게 유지하였다.

또한 이미지 수가 같다는 사실만으로 동일한 데이터라고 판단하지 않았다. 기존 로컬 실험에서는 이미지와 라벨 파일의 해시를 비교하여 검증·테스트 데이터의 내용이 일치하는지 확인하였다. 클래스 순서와 라벨 객체 수도 검사하여 클래스 ID가 다른 의미로 해석되는 문제를 방지하였다.

이 과정에서 데이터 관리가 모델 학습만큼 중요하다는 점을 확인하였다. 다만 해시가 다른 사진이라도 촬영 구도와 배경이 매우 비슷할 수 있으므로, 파일의 중복 검사만으로 데이터 누수 가능성을 완전히 배제할 수는 없었다. 향후에는 촬영 날짜나 촬영 세션을 기준으로 데이터를 분리하는 방식이 필요하다고 판단하였다.

7.2 학습 횟수와 최적 체크포인트를 구분하는 문제

25회, 50회, 75회 실험을 비교할 때는 각 실험의 출발점과 평가 가중치를 명확하게 구분해야 했다. 이전에 학습한 모델을 이어서 학습하면 학습 이력과 시작 가중치가 달라져 독립적인 비교가 어려워질 수 있다.

따라서 모든 실험을 동일한 사전 학습 모델인 yolov8n.pt에서 새로 시작하였다. 이를 통해 데이터 규모와 학습 횟수에 따른 변화를 비교하고자 하였다.

학습 완료 후에는 best.pt와 last.pt의 차이도 확인하였다. 학습 횟수가 75회라고 해서 75번째 에포크의 가중치가 가장 좋은 것은 아니었다. 실제로 최종 로컬 후보는 66번째 에포크에서 가장 높은 검증 mAP50-95를 보였고, Colab 후보는 49번째 에포크에서 가장 높은 값을 기록하였다.

이에 따라 마지막 가중치 대신 검증 성능을 기준으로 선택된 best.pt를 테스트하였다. 실험 폴더 이름을 잘못 지정한 경우에도 이름만 보고 모델을 판단하지 않고, 저장된 학습 설정과 이력을 확인하여 실제 학습 횟수를 구분하였다.

이 과정을 통해 실험 이름, 학습 한도, 최적 체크포인트의 시점을 서로 구분해야 한다는 점을 배웠다. 모델 파일과 성능표가 잘못 연결되지 않도록 최종 제출 자료에는 학습 조건과 체크섬을 함께 기록하였다.

7.3 Colab 실행 환경 초기화와 실험 재현성 확보

Colab에서는 연결 문제 이후 설치한 패키지나 데이터 변수를 찾지 못하고, 저장한 모델 경로가 존재하지 않는 상황이 발생하였다. 처음에는 인터넷 연결이 끊겨 모든 작업이 삭제된 것으로 생각하였지만, 브라우저 연결 상태와 런타임의 유지 여부를 구분할 필요가 있었다.

런타임이 종료되거나 새로운 실행 환경이 할당되면 메모리 변수와 설치한 패키지를 다시 준비해야 한다. 또한 임시 저장 공간인 /content에만 보관한 파일은 새 환경에서 사용할 수 없을 수 있었다. 이 때문에 학습이 완료되었더라도 모델과 데이터를 다시 불러오지 못하면 평가를 진행할 수 없었다.

문제 해결을 위해 패키지 설치, Google Drive 연결, 데이터 압축 해제 및 경로 확인, 모델 불러오기 순서로 환경을 복원하였다. dataset과 dataset_v2처럼 변수 이름이 다른 경우도 정리하고, 실제 파일이 존재하는지 확인한 뒤 다음 단계를 실행하였다.

이후에는 학습 결과를 Drive에 저장하고 ZIP 파일로도 백업하였다. 모델뿐 아니라 데이터 설정, 학습 이력, 평가 결과를 함께 보관하여 세션이 바뀌어도 실험 내용을 확인할 수 있도록 하였다.

Colab과 로컬 비교에서는 같은 seed를 사용하더라도 GPU와 소프트웨어 환경이 달라 결과가 완전히 같다고 보장할 수 없다는 점도 고려하였다. 따라서 두 환경의 작은 성능 차이를 GPU 자체의 우열로 단정하지 않고, 실행 조건과 측정 기준을 함께 기록하였다.

7.4 높은 테스트 성능과 실제 영상 추적 결과의 차이

정적 테스트셋에서는 대부분 높은 성능이 나타났지만, 새로운 영상을 적용하자 오분류와 박스 불안정, 추적 ID 변경이 확인되었다. 이는 테스트 지표만으로 실제 영상의 동작을 충분히 설명하기 어렵다는 문제였다.

로컬 모델은 원본 약 3.50초에서 마우스를 컵으로 잘못 분류하였다. Colab 모델은 해당 장면의 마우스를 올바르게 감지했지만, 마우스를 들어 올렸다 다시 놓는 과정에서 컵과 마우스의 추적 ID가 바뀌었다. 후반부 리모컨 조작에서도 ID 변경이 나타났다.

이 문제를 분석하기 위해 두 모델에 동일한 원본 영상과 추론 설정을 적용하였다. 프레임별 클래스, 박스 좌표, 신뢰도, 추적 ID를 CSV로 저장하고 같은 시점의 장면을 비교하였다. 이를 통해 객체의 클래스를 잘못 예측한 문제와 객체 사이의 추적 연결이 바뀐 문제를 구분하였다.

분석 결과, 최종 시연용으로는 주요 장면의 ID 연결이 상대적으로 안정적인 로컬 196장·75회 모델을 선택하였다. 그러나 로컬 모델에도 일시적인 오분류가 있었으므로 추적 문제가 완전히 해결되었다고 판단하지는 않았다.

또한 영상에는 프레임별 정답 박스와 정답 ID가 없었다. 따라서 예측 박스가 많이 출력되었다는 이유만으로 정확도가 높다고 판단하거나, 등장한 ID 수를 그대로 추적 오류 횟수로 계산하지 않았다. 이번 영상 비교는 정성적인 분석으로 범위를 제한하고, 정량적인 추적 평가는 향후 과제로 남겼다.

7.5 과제를 통해 배운 점

이번 과제를 통해 객체 감지 모델을 만드는 과정은 학습 명령을 실행하는 것으로 끝나지 않는다는 점을 배웠다. 데이터를 어떤 조건에서 수집하고, 어떤 기준으로 라벨링하며, 어떻게 분할하는지가 최종 결과의 신뢰성에 직접 연결되었다. 특히 잘못된 라벨이나 평가 데이터의 혼입은 모델 성능을 해석하기 어렵게 만들 수 있으므로, 학습 전 데이터 검사 과정이 필요하다는 점을 확인하였다.

학습 횟수와 데이터 수를 늘리는 효과도 직접 비교할 수 있었다. 처음에는 더 많은 데이터와 더 긴 학습이 항상 좋은 결과로 이어질 것으로 예상하였다. 그러나 실험에서는 데이터 증가 후 성능이 높아진 조건과 낮아진 조건이 함께 나타났다. 이를 통해 데이터의 양뿐 아니라 다양성, 클래스 구성, 라벨 품질과 학습 조건을 함께 고려해야 한다는 점을 배웠다. 작은 성능 차이의 원인을 하나로 단정하기보다 추가 실험으로 확인하는 태도도 필요하였다.

평가 지표를 해석하는 방법도 이해할 수 있었다. 모든 모델의 mAP50이 같더라도 mAP50-95에서는 차이가 나타났으며, 이를 통해 객체의 존재를 감지하는 것과 박스 위치를 정밀하게 맞추는 것이 다르다는 점을 확인하였다. 또한 검증 성능과 테스트 성능, 마지막 가중치와 최적 가중치를 구분해야 실험 결과를 올바르게 설명할 수 있었다.

실제 영상 비교에서는 객체 감지와 추적이 서로 다른 문제라는 점을 배웠다. 물체의 위치와 클래스를 올바르게 감지하더라도 이전 프레임의 객체와 연결하지 못하면 ID가 바뀔 수 있었다. 손 가림과 빠른 움직임, 카메라와의 거리 변화가 발생하면 정적 사진에서 드러나지 않던 문제가 나타났다. 따라서 실제 사용 가능성을 판단하려면 정적 테스트 지표와 영상의 동작을 함께 확인해야 한다고 느꼈다.

실험 결과를 보관하는 방법의 중요성도 경험하였다. Colab 환경이 초기화되었을 때 모델과 데이터 경로를 복원하지 못해 작업이 중단되었다. 이후 결과를 Drive와 로컬에 백업하고, 학습 설정과 성능 기록을 함께 보관하면서 재현성을 확보하는 습관이 필요하다는 점을 알게 되었다. 다른 사람이 코드를 실행할 수 있도록 경로와 설치 방법을 정리하는 과정도 실험의 일부였다.

마지막으로 높은 수치를 얻는 것과 그 결과를 신뢰할 수 있게 설명하는 것은 다르다는 점을 배웠다. 이번 테스트셋은 규모가 작고 같은 실물 물체를 중심으로 구성되어 있어, 새로운 물체나 환경에서도 같은 성능이 나타난다고 말할 수는 없다. 보고서에는 좋은 결과뿐 아니라 실패 사례와 평가의 한계도 함께 기록하였다. 이를 통해 모델의 성능을 과장하지 않고, 확인한 사실과 추가 검증이 필요한 부분을 구분하여 설명하는 경험을 얻었다.

8. 결론 및 개선 방향

8.1 에포크 수·데이터 수·실행 환경의 영향

에포크가 증가할수록 성능이 항상 높아지지는 않았다. Colab 414장 조건에서는 50회가 가장 높았고 75회에서는 소폭 낮아졌다. 데이터 증가 역시 일부 조건에서 도움이 되었지만 모든 실험에서 일관된 향상은 나타나지 않았다.

환경별 학습 시간에는 차이가 있었지만 테스트 성능의 우열은 조건에 따라 달랐다. 따라서 특정 GPU가 항상 더 정확한 모델을 만든다고 해석하지 않고 실행 환경과 학습 조건 전체를 고려하였다.

8.2 최종 모델 선정 근거

최종 시연 모델은 로컬 RTX 4060에서 196장으로 75회 학습한 best.pt로 선정하였다. 테스트 mAP50-95가 약 98.73%로 가장 높았고 새 영상의 주요 장면에서 Colab 후보보다 추적 연결이 상대적으로 안정적이었다.

Colab 414장·50회 모델도 테스트 mAP50-95 약 98.50%였으며 일부 장면에서는 로컬보다 올바른 결과를 보였다. 최종 선정은 현재 확보한 테스트와 영상에 근거한 선택이며 보편적인 우수성을 의미하지 않는다.

8.3 추가 데이터 및 다양한 환경에서의 개선 방향

다른 디자인과 색상의 컵, 마우스, 리모컨을 추가하여 특정 실물에 대한 의존을 줄일 필요가 있다. 어두운 조명, 복잡한 배경, 빠른 움직임, 심한 가림 등 실패 상황을 추가 수집하고 촬영 세션 단위의 분할을 적용하고자 한다.

평가에서는 독립적인 새 테스트셋을 확보하고 여러 seed로 반복 실험하여 평균과 변동을 확인할 필요가 있다. 추적은 프레임별 정답 ID를 구축한 뒤 감지 성능과 별도로 평가하고자 한다.

저장소에는 데이터 검사, 독립 학습, 테스트 평가, 영상 감지·추적 비교와 그래프 생성 코드를 포함하였다. 로컬 실행 명령과 Colab 노트북, 필요한 패키지와 데이터 준비 방법을 README에 정리하였다.

9.3 학습 모델 및 결과 동영상

실제 확보한 로컬 6개 모델과 Colab 최종 후보 1개를 models 폴더에 정리하였다. 최종 모델은 local_196_75_best.pt, Colab 비교 모델은 colab_414_50_best.pt이다.

최신 결과는 local_196_75_2x.mp4, colab_414_50_2x.mp4, comparison_2x.mp4로 저장하였다. 전체 2배속 결과는 약 6.72초이며, 원속도 비교 영상 comparison_full.mp4와 촬영 원본도 포함하였다. 강의자료의 5초 조건과 현재 길이의 차이는 제출 안내에 명시하였다.

9.4 성능 비교표·그래프·실험 설정

12개 실험의 테스트 지표 CSV, 클래스별 지표, 로컬 학습 시간과 비교 그래프를 포함하였다. 제공된 모델에 저장된 학습 이력을 추출하여 손실과 검증 성능 그래프도 작성하였다.
